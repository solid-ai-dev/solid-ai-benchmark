# 1. Introduction and goals

The benchmark measures whether an agent context file, a `CLAUDE.md`
generated by `solid-ai-templates` or a fork of it, makes an AI agent build
better software, and what it costs. It runs the same build many times,
changing only the file, and reads the difference under rules fixed before
the first run.

For a first reading with no technical background, start with the
[primer](../primer.md). This architecture is the one source of truth: how
the parts are built, every rule they follow, every threshold and every
decision. Each round's registration, fixed before its first trial, lives
under [`docs/rounds/`](../rounds/).

What it does:

- Generates each arm's context file from a fixed brief, with no person
  answering.
- Runs each trial in isolation: one agent session per build, cut off at a
  cost or a time bound.
- Freezes what the agent leaves, before anything reads it.
- Scores every frozen app with one ruler: hidden tests, attack probes,
  static tools, structural probes and a blind model judge.
- Pairs each trial with its no-file partner and computes a verdict per
  metric.
- Archives a round's raw data and verifies the archive before any report
  is written.

What it is not:

- It is not a test suite for this repository's own code. Each script has a
  `--self-test` for that.
- It is not a leaderboard of models. The model is held still, except where
  a round turns it as a knob.
- It does not ship or change the templates. It reads a templates source
  and writes reports into it.

## 1.2 Quality goals

The five goals that shape the architecture most, in order. Chapter 10
gives each its scenarios.

| # | Goal | What it means |
| - | ---- | ------------- |
| Q1 | Fairness | Every arm meets the same spec, model, prompt, bounds and ruler. Only the context file differs |
| Q2 | Pre-registration | The question, metrics and verdict rule are fixed before a trial runs, and the code enforces them |
| Q3 | Isolation | A trial reaches nothing it is defined not to have: the templates, the hidden suite, the web, another trial |
| Q4 | Honest measurement | A metric that was not measured reads missing, never zero. A grader that measured something else is withdrawn |
| Q5 | Reproducibility | Every input, revision and seed is recorded. A round can be restored and its report recomputed |

## 1.3 Stakeholders

| Role | Wants from the benchmark |
| ---- | ------------------------ |
| Owner of the templates | Evidence for or against each design choice, such as ADR-052 and ADR-058 in `solid-ai-templates` |
| Maintainer of a fork | A way to measure a trimmed or rewritten chain against the upstream baseline, head to head in one round ([ch. 4.2](04-solution-strategy.md)) |
| Adopter of the templates | A plain answer: will a generated file make my agent's code better, and what will it cost |
| Operator of a round | Commands that refuse a bad run before it costs money, and resume after an interruption |
| Reader of a report | Verdicts that say what they rest on, with their caveats beside them |

## 1.4 The idea in one example

Find out whether an agent given a `CLAUDE.md` generated by
`solid-ai-templates` builds a better application than the same agent with no
context file, given the same spec, model and tools, and at what cost.

**The idea in one example.** The agent builds the same app three times
without a context file and three times with one. Every build is scored on
each metric, so one metric gives three numbers per side.

Runs are compared with their partner, not side against side. Run 1 without
a file is compared with run 1 with a file, because the two ran on the same
day against the same model. The same goes for runs 2 and 3. The three
differences are what gets averaged.

| | run 1 | run 2 | run 3 | differences | verdict |
|---|---|---|---|---|---|
| without a file | 0.42 | 0.50 | 0.58 | | |
| with a file | 0.75 | 0.83 | 0.92 | +0.33, +0.33, +0.34 | **better**: every pair improved, by nearly the same amount |
| with a file, a metric that moved less | 0.45 | 0.60 | 0.70 | +0.03, +0.10, +0.12 | **better**: every pair improved, by an unsteady amount |
| with a file, a metric that did not move | 0.55 | 0.44 | 0.62 | +0.13, −0.06, +0.04 | **not shown**: two pairs improved and one got worse |

Overlapping columns say nothing on their own. The middle row's raw numbers
overlap, yet every pair moved the same way, so it reads **better**. Only the
bottom row, where the differences change sign, is undecided.

The report prints one such row per metric, the primary dimensions first. The
harness computes each verdict, so nobody decides one by eye.
